# 底部一体化聊天框（AgentDock）交互设计方案

> **版本**：v1.0（2026-06-01，定稿）
> **作者**：PM（结构化用户 × team-lead 逐条敲定的设计决策）
> **状态**：交互/需求方案**已定稿**（2 个开放点用户已拍板，见 §8）；技术迁移方案由 architect 另出
> **关联**：`ISSUES.md` #79
> **替换对象**：现有右下角悬浮气泡 `app/lib/widgets/agent_fab.dart`（AgentFab）
> **设计依据**：`docs/AGENT_SPEC.md` v1.1（三条横切原则、三级信任模型、4 核心场景）

---

## 0 一句话目标

把小浙从"右下角悬浮气泡"改造成"底部导航栏一体化的对话面板"——平时是导航栏的一部分（不喧宾夺主），需要时从底部长出对话区，引导时缩成一条窄条把屏幕让给原页面，收尾时原地渐隐收起。**保留已跑通的讯飞 ASR/TTS 语音全链路，仅替换容器形态。**

---

## 1 设计动机

| 现状（AgentFab 悬浮气泡） | 问题 | 新形态（底部 AgentDock） |
|---|---|---|
| 右下角可拖动小气泡，浮在页面之上 | 遮挡内容；老人不易发现/够不着；与高亮元素抢空间需复杂避让逻辑 | 固定在底部导航栏，位置稳定、好找好点 |
| 展开后浮层覆盖原页面 | 页面被盖住，看不清被引导的元素 | body 真压缩重排，原页面始终可见可操作 |
| 气泡需要"智能避让高亮区"（#47/#73） | 避让算法反复抖动、跨页坐标重置 | 面板在底部固定槽位，高亮靠自动滚动让位，无需避让 |

**核心理念**：面板是"对话的地盘在下、操作的地盘在上"，两者空间互不覆盖，由状态机按场景动态分配高度。

## 2 状态机（4 态）

### 2.1 状态总览

| # | 状态 | 面板高度 | 原页面 | 触发方 | 重心 |
|---|---|---|---|---|---|
| S0 | **收起态** | 0（仅导航栏） | 全屏 | 默认 / 收尾自动收起 | 看页面 |
| S1 | **半屏对话态** | ~50% | 压到上半屏，可滚动可操作 | 用户点小浙按钮 | 对话 |
| S2 | **引导态（窄条）** | 一条窄条（仅显示最近一条引导消息） | 占据绝大部分屏幕 | 后端进入引导流（自动） | 操作页面 |
| S3 | **卡片临时长高** | 窄条 → 刚好容纳卡片 | 略压缩 | 引导态需弹授权卡/选择卡 | 处理一事一授 |

> S3 是 S2 的临时子态：卡片处理完自动缩回 S2 窄条。

### 2.2 状态转换图

```
                  点小浙按钮
        ┌──────────────────────────────►┐
        │                                │
   ┌────┴─────┐                    ┌─────▼──────┐
   │   S0     │   后端进入引导流    │    S1      │
   │ 收起态   │◄───(几乎不直接) ────│ 半屏对话态 │
   │ 高度 0   │                    │  ~50%      │
   └────▲─────┘                    └─────┬──────┘
        │                                │ 后端进入引导流（自动缩窄）
        │ 收尾："办好啦"→停顿            │
        │  →平滑渐隐收起（自动）          ▼
        │                          ┌────────────┐
        │     用户点窄条「展开」    │    S2      │
        │   ┌──────────────────────│ 引导态窄条 │
        │   │  看完/打完→点「收起」 │            │
        │   └─────────────────────►│            │
        │                          └─┬───────▲──┘
        │       引导流结束             │       │
        └──────────────────────────────┘       │
                                  后端推授权卡/  │ 用户处理完
                                  选择卡(自动长高)│ (缩回窄条)
                                          ┌─────▼──────┐
                                          │    S3      │
                                          │卡片临时长高│
                                          └────────────┘
```

### 2.3 转换条件明细

| 从 → 到 | 触发 | 触发方 | 动效 |
|---|---|---|---|
| S0 → S1 | 点中间小浙按钮 | 用户 | 底部上滑展开至 50%，缓动 |
| S1 → S0 | 点「收起」（中间按钮变收起图标） | 用户 | 下滑收起 |
| S1 → S2 | 后端发引导流首条指令（如进入 login/医保引导） | 系统（自动） | 50% 平滑缩成窄条 |
| S2 → S1 | 用户点窄条「展开」控制 | 用户（临时插话/看历史） | 窄条上滑回 50% |
| S1 → S2 | 用户看完点「收起」 | 用户 | 回窄条（**引导进度不变**） |
| S2 → S3 | 后端推授权卡 / 选择卡 | 系统（自动） | 窄条按需长高到刚好容纳卡片 |
| S3 → S2 | 用户处理完卡片（授权/拒绝/选择） | 用户 | 缩回窄条 |
| S2 → S0 | 引导流走完 | 系统（自动收尾） | **原地播"办好啦"→停顿→渐隐缩小收起**（非弹出放大） |

**关键纪律（来自 AGENT_SPEC 原则 1「代理不主动」）**：
- S0→S1 永远是**用户主动**点按钮，系统绝不自动从收起态弹出对话。
- S1→S2、S2→S3、S2→S0 的自动切换都发生在**用户已唤醒后的引导流内部**，属于"被唤醒后的正常应答节奏"，不违反原则 1。

## 5 关键交互行为（逐条）

### 5.1 半屏态操作页面不收起面板
S1 下用户滚动/点击上半屏的原页面，面板保持 50% 不变。面板只由「收起」按钮或后端引导流切换关闭。

### 5.2 引导态自动进/出，用户可临时插话
- **进/出由后端驱动（主干自动）**：用户不需要手动"开始引导/结束引导"。后端发引导首条指令 → 自动 S1→S2；引导结束 → 自动收尾收起。
- **临时展开插话**：S2 窄条上点「展开」→ 回 S1 看历史/打字问一句。

### 5.3 引导中插话不打断引导流（受控响应）
用户在引导中途展开问一句、小浙作答后，**引导进度完全保持**（走到第几步、在等用户点哪个高亮元素，均不变）。答完用户收回窄条，回到原引导节奏继续。
- 契合 AGENT_SPEC「响应型 = 不主动挑事，只在用户有需求时介入」。
- 技术含义（交 architect）：插话走的是问答通道（参考现有 `cmd_ask_user` / OOS 应答），不重置引导执行器（`agent_command_executor`）的步进状态。

### 5.4 引导收尾：原地渐隐，不放大（用户特别强调）
引导流走完时**禁止切回半屏**（突然放大会惊吓老年用户）。收尾序列：
1. 就在 **S2 窄条原地**播报收尾语（文字 + TTS），见 §6.1。
2. 停顿（建议 1.5~2.0s，给老人读完/听完的时间，与 face_auth 成功停顿节奏一致）。
3. 面板**平滑渐隐 + 缩小**自动收起回 S0。

视觉本质：**渐隐缩小**（opacity↓ + height↓ 同步缓动），**不是弹出放大**。

## 6 文案规范

### 6.1 引导收尾语
- **主文案**：「已经帮您办好啦」
- 变体（按场景，保持口语、第一人称、不堆术语）：
  - 缴费类完成：「医保费帮您交好啦，您看一下～」
  - 查询类完成：「帮您查好啦，结果在上面」
- 语气：肯定、平和、像窗口工作人员收尾，不用感叹号轰炸（最多一个）。
- TTS 与文字**同步**，语速随用户在设置页选定的语速（沿用 `agent_settings_service`）。

### 6.2 控制项无障碍标签（语义标签，供读屏/语义树）

| 控件 | 可见 | semanticLabel | 说明 |
|---|---|---|---|
| 中间小浙按钮（S0） | (浙) 图标 + "小浙" | 「打开小浙助手」 | 点击区 ≥ 48dp |
| 中间按钮（S1，收起态图标） | ⌄ | 「收起小浙对话」 | |
| 窄条展开控制（S2） | ⌃ | 「展开小浙对话」 | |
| 麦克风按钮 | 🎤 | 「按住说话」 | 沿用 mic_button 现状 |
| 授权卡同意/拒绝 | [同意]/[拒绝] | 「同意小浙代填【字段名】」/「拒绝」 | 字段名动态注入（沿用 #69） |

### 6.3 文案纪律
- 全程不出现内部术语（trust_level / executor / highlight key 等）。
- 引导消息一条一句，窄条只显示**最近一条**完整不截断。

## 7 适老化考量（贯穿）

| 维度 | 要求 |
|---|---|
| **字号** | 对话正文 ≥ 18sp（对齐 PRD §4.1 全局最小字号）；引导窄条消息 ≥ 18sp 不截断 |
| **点击区** | 中间小浙按钮、收起/展开控制、卡片按钮均 ≥ 48dp |
| **对比度** | 长辈版橙 `#FF6D00` 主色，文字/图标对背景 ≥ 4.5:1；窄条与原页面要有明确分界（顶部阴影/描边） |
| **动效不惊吓** | 所有面板高度变化用缓动（建议 250~350ms ease）；**收尾必须渐隐缩小而非弹出放大**（§5.4）；引导态自动缩窄也要平滑，不要瞬跳 |
| **位置稳定** | 面板锚在底部固定槽位，不可拖动、不漂移（区别于旧 AgentFab 可拖动气泡——老人记得住"小浙在下面中间"） |
| **可见性** | 半屏态原页面始终露出上半屏，用户不失去场景上下文（AGENT_SPEC §7.1「用户仍可看见当前场景」） |

## 8 两个开放点决策（用户已拍板，定稿）

### 决策 1：中间小浙按钮造型 = **圆形凸起按钮** ✅

- **结论**：直径 ≥ 56dp 的橙色圆形按钮，略凸出导航栏（类似微信"+"/抖音中间键），内嵌卡通"浙"字小人图标 + 下方"小浙"文字标签。
- **理由**：适老化第一原则是"可预期、好辨认"，圆形主按钮是老人最熟悉的心智模型（电话/微信都这样），与 AGENT_SPEC §2「卡通浙字小人」形象一致，凸起强化"这是主入口"，带文字标签进一步降低识别成本。
- **被否决方案（记录）**：扇形/弧形仪表盘——形态隐喻不直观、可点区域不规则违背 ≥48dp 规整点击区、状态用形变表达对老人是认知负担，落入 persona 定义的"伪智能"风险。

### 决策 2：适用范围 = **本期只做长辈版** ✅

- **结论**：本期仅长辈版接入底部一体化 AgentDock；标准版列为**后续迭代**，不进本期。
- **理由**：
  1. 本毕设核心用户是老年人，学术叙事聚焦长辈版适老化，标准版是"对照/背景载体"。
  2. 标准版首页 `standard_home` 是**无底部导航页**，要做需为它补一套导航形态，改动大、收益低，且会稀释"适老化专项设计"的论证。
  3. 答辩演示全程走长辈版，标准版改造不在关键路径。
- **后续迭代（记录）**：若日后追求视觉一致性，标准版需新增底部导航容器并对齐 4 态。标准版现状（AgentFab 悬浮气泡或不挂）本期不改动。

## 9 迁移意图（替换 AgentFab，保留 ASR/TTS）

> 具体技术迁移方案由 architect 另出，此处仅声明产品侧意图，供技术方案对齐。

**保留（不动语音全链路）**：
- 讯飞 ASR：`audio_capture.dart`（Web Audio PCM 采集）+ `mic_button.dart`（按住说话）+ `agent_session.sendAudio` + `asr_result` 消息。
- 讯飞 TTS：`tts_adapter`（后端）+ 前端 7 类消息播放 + 队列化 + 跨页不打断。
- 会话/历史：`chat_history.dart`（ChatHistory 单例）、`agent_session.dart`、`ws_client.dart`。
- 代理执行链：`agent_command_executor.dart`、`agent_element_registry.dart`（高亮 key / applier）。
- 授权卡 / 选择卡：`auth_card.dart` + `agent_choice_request` 消息（在 S3 容器内复用渲染）。

**替换（容器形态）**：
- `agent_fab.dart`（AgentFab 悬浮气泡）→ 新底部 AgentDock 组件，挂到 `Scaffold.bottomNavigationBar` 槽位。
- 现有 `elder_bottom_nav.dart`（仅首页/我的两 Tab）→ 并入 AgentDock，中间补小浙入口按钮，并承载 4 态面板。
- 退役气泡避让逻辑（#47/#73 的 `_scheduleAvoid`/`_pickBubbleY` 等）——底部固定槽位后不再需要。

**高亮不被遮挡机制（architect 已核实，写此供参考）**：
- 面板挂 `bottomNavigationBar` → body 自动压缩重排，半屏/窄条天然生效。
- 高亮让位靠改进现有自动滚动：`Scrollable.ensureVisible` 的 alignment 0.85→0.5，且**面板高度变化后重触发一次**滚动；对半屏态、卡片长高态都生效。不再用卡片避让。
