## 第 6 页 · 核心设计一 · 三条全局原则

**标题**：核心设计一 · 三条全局原则

**①  代理永不主动**
唤醒前完全沉默，不弹窗、不打扰

**②  确定性操作止步**
登录 / 提交 / 支付 —— 最后一下用户亲手按

**③  分级授权 + 硬底线**
密码类字段，任何级别永不代填

**透明化机制（底部一行）**
执行前预告 → 执行中反馈 → 事后可追溯操作记录

〔图〕"去支付"止步点示意图（自制）

## 第 7 页 · 核心设计二 · 三级权限能力矩阵

**标题**：核心设计二 · 三级权限能力矩阵
**理论依据**：Parasuraman 自动化等级模型 · 自主性"连续谱"

| 能力 | 引导级 | 半委托级 | 全委托级 |
|---|:---:|:---:|:---:|
| 语音提示 + 元素高亮 | ✓ | ✓ | ✓ |
| 代填普通字段 | ✗ | ✓ | ✓ |
| 代填敏感字段 | ✗ | 逐次授权 | 一次总授权 |
| 密码 / 提交 / 支付 | ✗ | ✗ | ✗ 硬底线 |

**场景映射（底部）**
登录 = 引导级（最保守）　医保缴费 = 半 / 全委托　查询 = 全链路

## 第 11 页 · 测试发现与反思

**标题**：测试发现与反思

- **① 信任问题 > 易用性问题**：机制已做，深层不信任仍在
- **② 原则的内在矛盾**：越高风险，代理越帮不上
　（刷脸反复失败，代理只能语音引导、无法介入）
- **③ 一次挫败显著拉低整体评价**：容错与信任要贯穿全程

**反思（底部强调框）**
方向在常规场景合理；信任建立不能只靠架构固化 ——
正视这一矛盾，正是本研究的深度所在
