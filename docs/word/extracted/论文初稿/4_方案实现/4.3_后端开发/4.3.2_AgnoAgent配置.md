# 4.3.2 Agno Agent 配置

以医保缴费场景（L2–L3）为例：

agent = Agent(

model=DeepSeek(id="deepseek-chat"),

tools=[

cmd_navigate,

cmd_highlight,

fill_field_normal,            # 普通字段代填（L2）

fill_field_sensitive,          # 敏感字段代填（L3，触发 HITL）

],

session_id=session_id,

response_model=AgentInstruction,   # Pydantic schema，保证结构化输出

system_prompt=prompts["yibao_jiaofei"],

)

场景工具集白名单：每个场景在 agent_core.py 中维护独立的工具列表（SCENE_TOOLS），代理只能调用当前场景注册的工具——这是能力分级矩阵在代码层面的直接映射。L1 场景（如 login_face）只注册 cmd_navigate 和 cmd_highlight，从架构层面排除填字段的可能；L2 场景增加 fill_field_normal 和 read_sms；L3 场景再增加 fill_field_sensitive。

fill_field_sensitive 触发 HITL（Human-in-the-Loop）暂停机制：Agno 调用此工具前自动暂停代理执行，ws_handler 推送 permission_request 消息到前端，前端弹出授权卡片；用户同意后推送 permission_response（granted=true），后端恢复代理执行；用户拒绝则跳过该步骤并语音告知。

需要说明的是，本原型中部分工具使用模拟数据演示交互流程（如 read_sms 返回预设验证码 "123456"，fill_field_sensitive 使用预设脱敏身份证号），因为浏览器环境无法真实读取系统短信或证件信息。这并不影响对代理交互流程、授权机制和止步边界的验证——这些才是本研究关注的核心设计问题。

确定性按钮（cmd_press_button 对应的目标按钮名）在场景配置中通过白名单区分：只有查询类按钮（“查询”“搜索”）被允许代按，支付/提交/登录类按钮永远不在白名单内。无论代理生成什么指令，前端执行层会在 AgentCommandExecutor 中二次校验并拒绝执行。
