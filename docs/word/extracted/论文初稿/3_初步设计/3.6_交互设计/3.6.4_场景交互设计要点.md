# 3.6.4 场景交互设计要点

场景1：登录·刷脸分支（引导级，仅引导）。代理仅扮演解说员角色，语音引导每一步操作并高亮对应元素，但不帮用户点击任何按钮。针对摄像头权限弹窗这一高风险点，采用预告式语音引导，在弹窗出现前告知用户用途，将突发弹窗转变为有预期的步骤。刷脸动作引导用通俗语言替代技术性提示。用户在代理陪伴下独立完成刷脸登录。

场景2：登录·验证码分支（半委托级，代读代填）。代理升级为操作员，代读短信验证码并代填到输入框，但必须获得用户当场授权。采用一事一授权：进入验证码页面后先弹出授权卡片，用户同意后填充动画逐位显示数字填入过程，填完后提示用户核对。登录按钮始终由用户亲手点击，代理仅做高亮提示，确保用户保留最后一个决策动作。

场景3：医保缴费（半委托级–全委托级，含敏感字段授权）。代理展示完整的一事一授流程：普通字段（如缴费年度、金额等）直接代填并语音播报；身份证号等敏感字段弹出专门授权卡片，突出显示字段名称，填入后脱敏显示。逐字段代填均有语音播报，避免失控感。草稿箱机制自动保存未完成表单，下次唤醒时提示继续。“去支付”按钮高亮后代理静候用户操作，支付链路不跟入。

场景4：医保/养老金查询（引导级–半委托级，全链路）。此场景无确定性操作，代理可全链路完成：从唤醒到结果播报无需用户手动操作。查询结果采用双通道冗余：屏幕以大字卡片展示数字，同时语音播报结果，确保信息有效到达。查询按钮属于非确定性操作，代理可直接代按。
