# 3.3.1 受控响应型智能代理的设计原则

本研究提出的受控响应型智能代理遵循以下核心设计原则：代理原则上不主动；确定性操作代理止步；权限一事一授。受控响应型智能代理的设计原则贯穿所有设计决策，优先级最高，不因具体场景而妥协。

代理原则上不主动。代理在用户主动唤醒之前完全静默，不弹窗、不推送、不预判，将发起对话的权利始终留给用户。这一原则主要是基于老年用户在控制自主权上的需求。An在对老年人与智能体交互中自主性问题的系统分析中指出，控制自主性是老年人自主性的关键维度之一。该研究综述发现，许多老年人更偏好反应式智能代理，希望代理能够根据其需求做出响应，而非主动打扰[9]。Santini 等在研究表明，未经用户授权的主动提醒会让老年人产生“被监视或被施加压力”的感觉[10]。因此，本研究将代理定位为“响应式”而非“主动式”助手，用户始终掌握交互的发起权。

确定性操作代理止步。凡按下即产生不可撤销后果的操作，如登录、提交、支付等，代理只负责引导和告知，不代为执行，保障用户对最后一步的绝对掌控。这一原则参考了HITL（Human-in-the-Loop）设计范式中的“批准门”思想：在高风险或不可逆操作执行前设置人工确认节点，确保关键决策保留给人类。Adedokun 等在 HITL 框架的系统性综述中，将“自主性—责任差距”列为代理式 AI 系统面临的四大核心挑战之一，并指出 HITL 机制是弥合这一差距的重要设计策略[11]。Parasuraman 等在自动化模型中明确指出，在行动实施维度，保留用户对不可逆操作的最后执行权，可作为防止自动化错误的有效错误捕获机制[12]，这一点也对应了在本研究中以“登录”“支付”为代表的高风险操作交由用户控制的处理方式。此外，LaRubbio等的研究表明，老年用户在使用AI助手时高度关注隐私自主权，强调应通过设计让老年人成为主动决策者而非被动接受者[13]。因此，对于登录、提交、支付等不可逆操作，代理应当止步于引导和告知，将最终执行权始终保留给用户。

权限一事一授。 代理不持有持久化全局授权，每个涉及用户隐私或账户的敏感操作，均在当次任务中单独向用户请求授权，任务结束即失效。这一原则参考了任务粒度访问控制与最小权限思想。Chen和S在IETF草案中提出了面向AI代理的解耦授权模型，强调应实现细粒度、即时的权限授予，而非依赖长期身份或角色[14]。对于老年用户而言，模糊的持久化授权会加剧其对隐私泄露的担忧。因此，本研究将代理的授权范围严格限定在当前任务的当前步骤中，任务结束即权限失效，让用户始终保持对敏感操作的可控感。

本研究提出的三条设计原则分别从交互发起权、关键操作控制权和敏感信息授权三个维度，界定了受控响应型智能代理的行为边界。这些约束共同将代理的权限限制在用户可预期、可干预的范围之内。这一设计有助于增强老年用户对智能代理的可控感，缓解其对代理越权操作的深层焦虑。
