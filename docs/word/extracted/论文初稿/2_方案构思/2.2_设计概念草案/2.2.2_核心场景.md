# 2.2.2 核心场景

本研究聚焦四个老年人高频使用且痛点突出的核心政务服务场景。

第一，账号登录·刷脸分支。当系统弹出人脸识别授权弹窗时，代理不介入该授权操作，恪守边界止步原则。进入人脸认证环节后，代理进入引导协助状态，通过文字提示与语音引导相结合的方式，帮助老年用户完成眨眼、摇头等动作要求，降低用户面对机器指令时的困惑与紧张感。这一场景展示了代理对系统级安全弹窗不介入的边界原则，以及在用户授权后的引导环节提供多模态协助的能力。

第二，账号登录·验证码分支。该场景涉及跨应用操作，老年用户常因需要切换至短信应用查看验证码而中断流程，甚至因页面超时导致操作失败。代理在获得用户授权后，可代为读取短信验证码并帮助填入输入框，但止步于点击登录按钮这一确定性操作，交由用户亲手完成。这一场景展示了代理跨应用协助的能力与确定性止步的设计逻辑：代理可进入信息获取环节，但绝不触碰提交类关键节点。

第三，医保缴费。该场景涉及大量表单信息填写，老年用户在地址、身份证号、联系方式等字段上极易出错或产生畏难情绪。代理可代为填写常规字段，但当涉及身份证号等敏感信息时，须在当前任务中单独向用户请求临时授权，获得明确同意后方可填入；缴费确认环节同样止步，由用户自行核对并提交。这一场景展示了权限一事一授的完整流程，以及敏感信息与常规信息分级授权的设计机制。

第四，医保/养老金查询。该场景为查询类任务，全程不涉及提交、支付等确定性操作。代理在获得用户一次性授权后，可在用户确认启动后全自动完成从进入页面到信息提取的全链路操作，并将查询结果以清晰可读的方式呈现给用户。这一场景展示了在无安全风险的前提下，代理以最小打扰实现最高效率的全自动路径，体现了授权层级与代理自主程度之间的灵活匹配。
