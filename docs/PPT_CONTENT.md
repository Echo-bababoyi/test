## 第2页｜核心创新：受控响应型代理三原则

**建议时长：** 40秒

### 标题文字
> 核心创新：受控响应型代理

### 副标题
> 与现有AI助手的本质区别

### 正文要点（5条）
1. 现有AI助手：只回答，不操作
2. 本系统：直接代填表单、跳转页面、读取验证码
3. **原则一：不主动** — 不唤醒，永远静默
4. **原则二：止步确定性操作** — 支付/登录用户亲手点
5. **原则三：权限一事一授** — 无全局授权，逐次请求

### 补充说明行（页面底部小字）
> 三原则固化为架构约束，非运行时约定 — 越权在技术上不可能发生

### 副标题

### 矩阵表格内容

| 能力项 | L1 引导 | L2 半委托 | L3 全委托 |
|---|:---:|:---:|:---:|
| 语音对话 + 意图理解 | ✓ | ✓ | ✓ |
| 页面跳转 | ✓ | ✓ | ✓ |
| 屏幕高亮引导 | ✓ | ✓ | ✓ |
| 代填非敏感字段 | — | ✓ | ✓ |
| 敏感字段（需单独授权） | — | — | ✓ |
| 确定性操作（登录/支付） | ✗ | ✗ | ✗ |

- 刷脸登录 → L1

- 医保缴费 → L2–L3（含身份证授权）
- 查询类 → L1–L2 全链路自动

页面居中放矩阵表格（占页面60%高度），表格下方一行小字标注4个场景对应等级。最后一行"✗"建议换成红色X并加红色行背景色以强调硬性底线。

## 第4页｜场景演示：登录

**建议时长：** 35秒

### 标题文字
> 场景1：账号登录

### 副标题
> 刷脸分支 + 验证码分支

### 左栏：刷脸分支（3条）
1. 痛点：摄像头权限弹窗令老年人恐慌
2. 解法：弹窗出现**前**，代理语音预告
3. 效果：突发弹窗变为有预期步骤

**代理台词示例（小字引用框）：**
> "马上会弹出摄像头请求，这是刷脸认证用的，请点同意"

### 右栏：验证码分支（3条）
1. 痛点：切出APP查短信，页面超时失效
2. 解法：代理弹出授权卡，代读代填验证码
3. 止步点：填完后高亮"登录"按钮，用户亲手按

**代理台词示例（小字引用框）：**
> "这次我帮您读验证码并填上去，可以吗？"

### 情感设计备注（底部小字）
> 两个分支共同目标：用户感受到"这次登录是我自己完成的"

### 图片需求
| 编号 | 内容 | 来源/截图方式 |
|---|---|---|
| 图4-1 | 刷脸验证页 + 代理气泡预告 | 运行原型：进入 `/login/face`，小浙气泡显示摄像头预告文字时截屏 |
| 图4-2 | 验证码授权卡片弹出状态 | 运行原型：进入 `/login/verify`，授权卡片出现时截屏 |

### 布局建议
左右两栏各放一个场景，栏间加竖分隔线。每栏：截图在上（约50%高度）+ 要点3条在下。标题跨两栏居中置顶。

## 第5页｜场景演示：医保缴费

**建议时长：** 40秒

### 标题文字
> 场景2：医保缴费

### 副标题
> 最复杂场景 — 权限一事一授完整演示

### 流程要点（5条，按操作顺序）
1. 代理自动填入：缴费对象 / 年度 / 金额 + 逐步语音播报
2. 身份证号：单独弹出授权卡，24sp粗体字段名
3. 填入后脱敏显示：`330…**…6`
4. 止步于"去支付"：高亮按钮，代理不再操作
5. 草稿箱：中途离开自动保存，下次续填

### 重要标注
> 支付链路代理不跟入 — 物理隔离，非行为约束

### 代理台词示例（两个引用框）
> "还需要填一下身份证号，这次我帮您填可以吗？"

> "表单已填好，请您确认后点击橙色的去支付按钮"

| 图5-2 | "去支付"橙色高亮止步状态 | 运行原型：代理填完所有字段，"去支付"按钮高亮、代理停止时截屏 |

## 第7页｜交互设计亮点

**建议时长：** 30秒

### 标题文字
> 交互设计亮点

### 模块一：代理面板叠加（2条）
- 浮层叠加，业务页面始终可见
- 用户不迷失位置，随时可手动接管

### 模块二：悬浮助手 AgentFab（2条）
- 52dp 可拖动，松手自动吸边
- 随叫随到，不占底部导航栏

### 模块三：适老化视觉规范（3条）
- 全局最小字号 18sp，授权卡 24sp Bold
- 所有触控区 ≥48dp，麦克风按钮 88dp
- 橙色主色满足 WCAG AA 对比度标准

### 模块四：容错设计（2条）
- 识别失败：最多重试3次，优雅退出
- 网络断开：红色横幅明示，不静默失败

## 第8页｜技术实现亮点

**建议时长：** 25秒

### 标题文字
> 技术实现亮点

### 四个技术模块

**前端**
- Flutter Web · GoRouter · 17页面
- AgentElementRegistry 跨树元素高亮定位

**后端**
- FastAPI · Agno Agent · DeepSeek-V3
- WebSocket 双向实时通信

**多模态**
- 讯飞 ASR 语音识别
- 讯飞 TTS / Edge TTS 按需合成
- MediaPipe 本地化部署（零CDN依赖）

**工程亮点**
- 确定性按钮物理隔离（代码层永不注册为工具）
- 权限状态随 WebSocket 会话消亡
- 草稿箱 IndexedDB 本地持久化

## 第9页｜成果总结 + 学术贡献

**建议时长：** 35秒

### 标题文字
> 成果总结与学术贡献

### 贡献一：设计框架
**受控响应型代理框架**
- 三原则固化为架构约束
- L1/L2/L3 分级授权矩阵
- "信任保障"从对话约定升级为可验证工程性质

### 贡献二：方法论
**多模态冗余互补方法论**
- 语音 · 视觉 · 触控三模态时序对齐
- 任一感官通道退化不影响信息接收

### 贡献三：范式路径
**协助服务范式**
- 政务大厅协助模式数字化复刻
- 可向医疗 / 金融 / 生活服务 APP 推广

### 可用性测试计划（底部单独一行）
> 5–8位老年用户 · 4场景任务 · 任务完成率 + SUS量表 + 信任感评分

### 图片需求
无需截图，三贡献以卡片形式展示即可。

### 布局建议
三张卡片横向并排（各占约30%宽），每张卡片：粗体标题（20pt）+ 分隔线 + 3条要点（16pt）。底部横跨全宽放可用性测试计划一行（灰色背景小字）。
