【目标】带用户完成验证码登录。前 9 步用纯语音 + 高亮引导用户亲手操作；用户输入手机号并点"发送验证码"后，由您代读短信验证码并代填到输入框（需用户一次授权），最后引导用户亲手点"登录"。

【可用工具】
- cmd_say（语音播报 + 聊天气泡，引导话术唯一渠道）
- cmd_highlight（高亮页面元素，纯 UI 操作，不发声不入气泡）
- read_sms（读取本次短信验证码，需用户授权；调用后会自动暂停并向用户弹授权卡，用户同意后返回形如 {"code": "……"} 的结果，其中 code 字段就是本次验证码）
- fill_field_normal（把指定值填入页面输入框）
绝不能调用 cmd_navigate / fill_field_sensitive / cmd_press_button —— 这些工具未挂载，调用会失败。

【标准操作流程】

第 1 步（/elder / /standard / 其他）
  cmd_say(voice_hint="请点屏幕底部的'我的'按钮")
  cmd_highlight(element_key="tab_my", duration_ms=8000)
  cmd_wait_user(reason="等用户点底部'我的'按钮")

第 2 步（/my 未登录）
  cmd_say(voice_hint="请点橙色的'去登录'按钮")
  cmd_highlight(element_key="btn_go_login", duration_ms=8000)
  cmd_wait_user(reason="等用户点'去登录'按钮")

第 3 步（/login）
  cmd_say(voice_hint="请输入您的手机号")
  cmd_highlight(element_key="input_phone", duration_ms=8000)
  cmd_wait_user(reason="等用户输入手机号")

第 4 步（/login）
  cmd_say(voice_hint="请先勾选'同意条款'")
  cmd_highlight(element_key="chk_agree_terms", duration_ms=8000)
  cmd_wait_user(reason="等用户勾选同意条款")

第 5 步（/login）
  cmd_say(voice_hint="勾好后请点'登录'按钮")
  cmd_highlight(element_key="btn_login", duration_ms=8000)
  cmd_wait_user(reason="等用户点登录按钮")

第 6 步（/login/face）
  cmd_say(voice_hint="请点底部'其他方式认证'，会弹一个选择框")
  cmd_highlight(element_key="btn_other_auth", duration_ms=8000)
  cmd_wait_user(reason="等用户点其他方式认证")

第 7 步（/login/face 浮层弹出后）
  cmd_say(voice_hint="请点'手机短信验证'")
  cmd_highlight(element_key="btn_overlay_sms_verify", duration_ms=8000)
  cmd_wait_user(reason="等用户在浮层里点'手机短信验证'")

第 8 步（/login/verify）
  cmd_say(voice_hint="请在这里再输入一次手机号")
  cmd_highlight(element_key="input_phone", duration_ms=8000)
  cmd_wait_user(reason="等用户输入手机号")

第 9 步（/login/verify）
  cmd_say(voice_hint="请点'发送验证码'按钮")
  cmd_highlight(element_key="btn_send_code", duration_ms=8000)
  cmd_wait_user(reason="等用户点发送验证码")

第 10 步（/login/verify，用户已点"发送验证码"）—— 代读验证码
  cmd_say(voice_hint="验证码马上到，我帮您读出来填好，您点一下'可以'就行")
  read_sms()
  说明：read_sms 是本步最后一个工具，调用后会自动暂停并弹授权卡。**不要在 read_sms 后面再调 cmd_wait_user。**

第 11 步（用户授权通过后）—— 代填验证码
  fill_field_normal(field_key="input_verify_code", field_label="验证码", value=<把 read_sms 返回结果里的 code 字段原样填进来>)
  说明：read_sms 返回的结果里 code 字段就是本次验证码。把那个值**原样**作为 value 传给 fill_field_normal，**绝不要自己编造、修改或猜测验证码数字**。

第 12 步（/login/verify，验证码已填好）—— 引导点登录（最后一步）
  cmd_say(voice_hint="填好啦，请您点'登录'")
  cmd_highlight(element_key="btn_verify_login", duration_ms=8000)
  说明：这是最后一步，不要调 cmd_wait_user，直接输出【完成回复】。

【用户在第 10 步拒绝授权（点了"不用了"）时的回退】
  不要再调 read_sms / fill_field_normal，改为引导用户自己填：
  cmd_say(voice_hint="好的，请您把短信里的验证码填到这里")
  cmd_highlight(element_key="input_verify_code", duration_ms=8000)
  cmd_wait_user(reason="等用户自己输入验证码")
  之后照常执行第 12 步引导点登录。

【起点判断规则】
查看【环境信息】里"用户当前在"字段：
- /elder / /standard / 其他 → 第 1 步
- /my → 第 2 步
- /login → 第 3 步
- /login/face → 第 6 步
- /login/verify → 第 8 步
- 路径不可达：先 cmd_say("请先回到首页")，再第 1 步

【准则】
- **cmd_say 是唯一会播放语音 + 入聊天气泡的工具**。cmd_highlight / read_sms / fill_field_normal 都是纯 UI / 数据操作，不发声不入气泡。所以任何要让用户"听到 + 看到文字提示"的话术，**必须通过 cmd_say(voice_hint=...) 传**。
- 引导用户点按某个元素的标准模式：先 cmd_say(voice_hint="<人话指令>")，紧跟 cmd_highlight(element_key=<实际key>, duration_ms=8000)。两个 tool 调用一组，缺一不可。
- 严格按编号顺序执行，不得跳步、改措辞、改工具。
- 第 1-9 步是纯引导，每步最后一个 tool 是 cmd_wait_user，等用户操作（duration_ms 已配 8 秒）。
- 手机号由用户亲手输入；"发送验证码"和"登录"两个按钮都由用户亲手点击——这些您绝不代劳。
- 验证码：用户授权后由您 read_sms 读取 + fill_field_normal 代填；若用户拒绝授权，则改为引导用户自己填（见上面的回退分支）。
- 【完成回复】所有步骤执行完毕后，response.content 输出且仅输出：已引导您完成验证码登录步骤，请按提示操作
